# ArcRPGMechanics Plugin

Layer L3: ArcRPG rules layered on ArcMassMechanics (L2). Runtime module `ArcRPGMechanics`; no content. Depends on ArcMassMechanics, ArcMassAbilities, ArcMassDamageSystem, ArcAbilityKit, ArcMassItems, ArcNeeds, ArcCore. The ArcRPG game feature (L4) consumes it; this plugin never depends on ArcRPG.

- Gameplay tags are native C++ in `ArcRPGMechanicsTags.{h,cpp}`; numbers are editor data on the type or asset that uses them. There are no developer settings.
- Log category: `LogArcRPGMechanics`. Tests: `Tests/ArcRPGMechanicsTest`. No editor module; data checks are `IsDataValid` on the config assets and the execution's `GatherDataWarnings` (reported by the L2 `UArcDamageTypeValidator`).
- A rule that needs no ArcRPG type belongs in L2.

## Inventory and what it overrides

| Area | Types | Overrides or fills (L2/AMA owner) |
|---|---|---|
| Attribute sets | `FArcAttributeSet_RPG{CoreStats,Skills,Energy,Stamina,Entropy,HealthExtension}`, `FArcSurvivalAttributeFragment`, `FArcRPGAttributeSet_{Passives,ItemArmor,SpellDamage,StatusDuration,CostAffixes}` | `RPGEnergy` and `RPGStamina` also hold the D-100 pip attributes (`EnergyRegenPips`, `EnergyDegenPips`, `EnergyPerPip`; `StaminaRegenPips`, `StaminaDegenPips`, `StaminaPerPip`), read by the L2 Pips rate; `RegenPips` and `PerPip` bases come from `Linear` handlers (WIS/MAG, CON/AGI), `DegenPips` only from modifiers. Resource sets expose the meta attributes that `FArcAttributeHandler_MetaToResource` writes into; the `Damage` meta is written into Health by `FArcAttributeHandler_HealthDamage`. `ItemArmor` (`Armor`, `Resistance`) are Item Stats keys read from items, tagged per damage type. `SpellDamage` (`SpellDamagePct`), `StatusDuration` (`StatusDurationPct`) and `CostAffixes` (`EnergyCostPct`, `EntropyGenerationPct`) are caster fractions set by item effects. Global per-type `Armor` and `Resistance` are modifiers on L2 `FArcAttributeSet_Mitigation` whose `SourceTagRequirements` require the damage type. |
| Derived values | `FArcRPGAttributeHandler_{MaxHealth,MaxStamina,MaxEnergy,MaxEntropy,Linear}` (`ArcRPGDerivedValueHandlers.h`), `FArcRPGAttributeHandler_NeedRates`, `ArcRPGCoreDerivation` | One handler per derived attribute, observing only base attributes (a handler's write does not notify observers). A handler writes `Context.Attribute` and declares its inputs in `GatherInputs`. Max handlers fill their resource at spawn (not Entropy) and clamp it when the max drops. MaxStamina/MaxEnergy apply the fatigue pool `max(0.25, 1 - Fatigue x 0.005)`. `Linear` writes `Base` plus its `FArcRPGChanceTerm`s (per point or per modifier; a missing input adds 0); it serves `ThresholdEntropy`, each `FArcRPGAttributeSet_Passives` value and the hit chain chances. `NeedRates` sits on Constitution, observes STR and WIL, and writes need change rates plus hunger/thirst resistance. Numbers are handler fields. `CalculateModifier` is the one attribute modifier (D-08). |
| Skill caps | `FArcRPGAttributeHandler_SkillCap` | One instance per skill max: lowest of `CapAttributes` (the pair, or Magic) x `PointsPerAttribute`; clamps the skill down when the cap drops. `GatherInputs` reports `CapAttributes`. |
| Costs | `FArcRPGCost_Ability`, `ArcRPGItemCost::GetEntropyGenerated(EM, Entity, Handle)` | One cost per ability. It reads five stats of the source item's `FArcRPGItemFragment_AbilityStats` at the ability level (item found through `ArcAbilityKit::FindSourceItem`); a stat at 0 does nothing. `EnergyCost`: `x EnergyChanneling x max(1, CascadeMultiplier)^stacks x max(0, 1 + EnergyCostPct)`, needs `Energy`, paid through `RemoveEnergy`. `EntropyCost`: flat, needs `Entropy`, paid through `RemoveEntropy`. `HealthCost`: needs `Health`, paid through `DegenDamage`. `StaminaCost`: needs `Stamina`, paid through `RemoveStamina`. `EntropyGenerated`: `x Weaving (only when the item tags have ArcSpell.Woven) x EntropyChanneling x max(0, 1 + EntropyGenerationPct)`, added through `AddEntropy`; it never blocks and is skipped when the entity has no `AddEntropy`. The check reports the first failure in the order Energy, Entropy, Health, Stamina, and nothing is paid unless all pass. A missing item fails. `EntropyCost` and `EntropyGenerated` both > 0 is a config error: item validation reports it, and at runtime the cost fails `Unsatisfied` and pays nothing. `ApplyCost` pays through the L2 `ArcCosts::PayIntoMeta`. `GetEntropyGenerated` returns the generated amount of the ability's `FArcRPGCost_Ability` (top-level or inside an `FArcCost_Set`), shared by the cost and Surge. |
| Cascade | `FArcRPGItemFragment_CascadingCost`, `FArcRPGItemInstance_CascadingCost`, `FArcRPGAbilityTask_CascadeIncrement`, `FArcRPGCooldown_CascadeReset` | Cascade count lives on the item instance; the increment task adds one per cast, the cooldown slot resets it. |
| Surge | `FArcRPGAbilityTask_SurgeTier` | Own ability task (not a threshold-tier subclass): `ValueAttribute + GetEntropyGenerated - ThresholdAttribute` through `Bands`; table key is the spell domain tag (`ArcSpell.Element.*`) in the source item's Item Tags; writes `Magnitude` and `Tier`. |
| Resources | `FArcRPGResourceRate_AttributeModifier` | `FArcResourceRate` slot: `max(0, BasePerSecond x (1 + ModifierScale x modifier(Attribute)))`, read live. Entropy regen only (WIL, Min target). Energy and Stamina use the L2 Pips rate (D-100). |
| Statuses | `FArcRPGStatusDurationCalculation` | The duration calculation (AMA slot): skill step (`Base x (1 + Scale x skill power)`, skill power from the source item's Skill Scaling fragment through a snapshot capture, 0 without it) x WIS x `(1 + StatusDurationPct)`; world-time effect types scale by game hours. |
| Hit chain | none (the gate is the plain L2 `FArcMechHitGate`) | Chances on `FArcAttributeSet_HitChain` come from `Linear` handlers. Defense rules (who may parry or block what) and Aiming are tag-qualified modifiers on the chance attributes, authored in effect data (see `docs/reference/mechanics-test-assets.md` "Combat hit chains"). `Armed` / `Shield` (`ArcRPG.Defense.*`) are tags describing the defender's equipment; an entity that cannot dodge has `DodgeChance` 0. |
| Triggers | `FArcRPGTriggerCondition_SameSourceItem` | `FArcTriggerCondition` slot, If only: met when the hit's `FArcAbilitySource_Item` and the host effect's carry the same item id (the handle is not dereferenced); either side without an item is not met. |

## Damage

`FArcRPGDamageExecution` derives from the empty L2 `FArcDamageExecutionBase` (so `UArcDamageTypeValidator` checks its effects), runs the `combat.yaml` pipeline and calls the L2 `ArcMechCombat` helpers, passing every value. It writes `FArcAttributeSet_Damage::Damage` (fixed in code). One effect is one hit of one damage type, the effect's own `ArcEffect.Damage` tag (D-96); a weapon's extra damage type is another effect authored by content.
- **Path** (`ArcRPGAttackPath::Resolve` on the captured source tags): `ArcRPG.AttackClass.Weapon` is the weapon path, `ArcRPG.AttackClass.Spell` the spell path, neither or both uses the authored `Base` and `Scale` and no `SpellDamagePct`. The path decides only the weapon base and `SpellDamagePct`; the skill and attribute steps follow the Skill Scaling fragment on any path.
- **Source item**: the item that granted the ability (`ArcAbilityKit::FindSourceItem`), not the quickbar's active weapon. Four hidden extra capture sources (`ArcRPGSourceItemSources.h`) read it, and every one is a snapshot resolved when the spec is built; the item is read only at spec build, because the item handle is a raw pointer that periodic ticks outlive (a child spec built later copies the source data and resolves its own snapshots at its own build). A source fails when there is no item, no fragment or an unset field.
- **Weapon base**: the source item's Damage and Scale (`FArcRPGScalableFloatItemFragment_WeaponDamage`), on the weapon path only. With no captured weapon (no item, no fragment, spell path, neither path tag), the authored `Base` and `Scale` apply. `WeaponMultiplier` multiplies the base.
- **Skill Scaling fragment** (`FArcRPGItemFragment_SkillScaling`, a regular item fragment, looked up on the item definition through `GetFragment`): `Skill` (attribute), `Scaling` (`FArcValueScaling` curve), `Attribute` and `K`. Skill power = `Scaling.Power(source entity's Skill, ArcRPGSkillScaling::SkillMax)`, `SkillMax` a `constexpr` 100. Attribute factor = `max(0, 1 + K x ArcRPGCoreDerivation::CalculateModifier(Attribute))`. An unset `Skill` or `Attribute` skips its step; a failed capture gives power 0 and factor 1. The fragment also drives the status duration's skill step.
- **Config assets**, each referenced by every effect that uses it; a missing asset turns off its own step:
  - `UArcRPGHitZoneConfig`: weighted `Zones` (children of `ArcMech.Hit.Zone`). Without it no zone.
  - `UArcRPGArmorConfig`: the armor curve and `ArmorK` (ClampMin 0.01). Without it no armor curve.
- **Crit** is the L2 attribute set `FArcAttributeSet_Crit` on the attacker; there is no crit config. An attacker without the set, or whose `CritChance` capture fails, rolls no crit.
- **Value**: skill step `Base x (1 + Scale x skill power)`, `x attribute factor`, `x max(0, 1 + SpellDamagePct (spell path) + OutgoingBonusPercent - OutgoingReductionPercent)`, x crit, flat outgoing bonus and reduction, target incoming bonus, mitigation. Every attribute is read with the spec's captured source and target tags passed unchanged (the definition's damage type is in the source tags), plus the zone in the target tags on applied hits; modifiers qualify by their `SourceTagRequirements` / `TargetTagRequirements`.
- **Applied hits only**: crit roll (`FRand() < CritChance + If CritChance`; on a crit the multiplier is `max(0, CritMultiplier + If CritDamage)`, `CritMultiplier` being the full multiplier), zone roll by weight, with the If `CritChance` modifiers added to the chance before the roll; then the other If channels (`CritDamage` on a crit only, Done multiplier after the percent term, Done flat with the flat bonus, Taken at the incoming bonus), whose conditions see crit and zone; `CommitIf` after the damage is final. Periodic ticks roll no crit and no zone.
- **Armor and resistance**: final armor = the struck piece's armor + global `Armor`; final resistance = the piece's intrinsic resistance + global `Resistance`. The zone sources pick the defender's items that sit in a slot, are active and carry the struck zone tag, and read the highest `ItemArmor` value for the hit's damage type; pieces never sum. A periodic tick has no zone, so the piece gives 0 and only the global values apply (D-91 5d).
- **`ValueTiming`**: `AtApplication` (default) stores every attacker and target input (spell damage, outgoing flat/percent/caps; target incoming flat/percent/cap, damage reduction, global armor and resistance) in `CaptureApplicationState` and periodic ticks reuse it; `EveryExecution` reads them live at every tick. Weapon Damage and Scale, skill power and attribute factor are snapshots in both modes: a DoT does not follow skill or attribute changes made after the cast.
- **Events**: every execution publishes Hit and, above 0, Damage Dealt (see ArcMassMechanics `CLAUDE.md`).

## Contracts

- Item-source reads go through `ArcAbilityKit::FindSourceItem`, only inside a snapshot extra capture resolved at spec build.
- Damage reaches `FArcRPGDamageExecution` behind the L2 hit gate; true damage bypasses it (see ArcMassMechanics `CLAUDE.md`).
